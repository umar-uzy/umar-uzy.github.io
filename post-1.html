What QA taught me about writing better requirements

Most of the bugs I file aren't really code bugs. By the time something reaches me, the code usually does exactly what it was told to do — the problem is that what it was told to do was never quite right in the first place. The requirement was ambiguous, or it assumed a happy path that doesn't hold up, or it just left a case unmentioned.

Once I started paying attention to that pattern, I began catching a lot of issues earlier — before a single test case was written, let alone run.

Where ambiguity hides

A few places I've learned to slow down and ask questions before testing even starts:

Undefined edge cases. A requirement that says "the user enters their email" rarely says what happens with a typo, a duplicate, or an empty field. Someone will decide that behaviour eventually — better it's a product decision than whatever the code happens to do by accident.

Implied state. Requirements often describe one screen without saying what should already be true to reach it. What if the cart is empty? What if the session expired mid-flow? These aren't edge cases so much as unstated assumptions.

Words doing too much work. "The page should load quickly" isn't testable until quickly means something — 200ms, 2 seconds, "before the spinner would look broken." Vague adjectives are where two people can each be confident and still disagree.

If I can't write a test case for a requirement without guessing, that's not a testing problem — it's a requirement that isn't finished yet.

What I do differently now

I've started raising these questions during planning rather than saving them for the bug tracker. It's a small shift, but it changes the tone completely — instead of "this is broken," it's "what should happen here?" One is a defect, the other is a design conversation, and the second one is a lot more useful to everyone involved.

It's also made me a better reader of specs generally, on this blog included — vague adjectives are easy to spot once you're used to hunting for them.
